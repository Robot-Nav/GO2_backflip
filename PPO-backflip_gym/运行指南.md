# Unitree Go2 EDU 后空翻真机运行指南

本文记录本项目已经实际走通的 Go2 EDU 网络连接、服务设置、通信检查、
无翻转接管验证和单次后空翻运行流程。

> 后空翻可能造成人身伤害和机器人损坏。MuJoCo PASS、程序显示 READY 以及
> 已有成功测试均不构成硬件安全保证。真机运行必须使用顶部保护绳或保护架、
> 大面积软垫和独立的手柄操作人员，并清空机器人前后翻转区域。

## 2. 机械与人员安全准备

1. 电池电量充足，机器人没有电机、关节、通信或温度故障。
2. 四脚放在平整防滑地面，机身基本水平，腿部没有被绳索或支架卡住。
3. 顶部保护绳只负责限制跌落，不能在正常起跳时拉住机身或阻碍俯仰旋转。
4. 地面铺设足够大的软垫，清空机器人前后翻转平面。
5. 一名操作人员只负责双手手柄，手指随时准备按 `SELECT`。
6. 其他人员全部离开运动区域。
7. 确认手柄已经和 Go2 配对，`START`、`A`、`SELECT` 按键可用。
8. 退出程序前必须有人扶住机器人，因为退出会切换到阻尼状态。

`SELECT`/`Ctrl-C` 只是切换到阻尼命令，不是在空中悬停或制动。机器人在
空中进入阻尼后仍会跌落，因此急停不能替代保护架和软垫。

## 3. 手机 App 服务设置

先在手机 App 中让机器人进入阻尼模式，并由人员或保护架支撑机器人，然后
进入服务状态页面，设置为：

```text
mcf         关闭
sport_mode  关闭
ota_box     启动
```

即：

1. 手机 App 关闭 `mcf`。
2. 保持 `sport_mode` 关闭。
3. 启动 `ota_box`。

不要批量关闭以下受保护或基础服务：

```text
robot_state
basic_service
master_service
motion_switcher
```

不要让手机 App、其他 SDK 控制进程和本项目后空翻程序同时发送运动指令。
部署程序启动时还会通过 MotionSwitcher 检查并释放残留的内置运动模式。

可选：用 SDK 查看当前服务状态：

```bash
python -c '
from unitree_sdk2py.core.channel import ChannelFactoryInitialize
from unitree_sdk2py.go2.robot_state.robot_state_client import RobotStateClient

ChannelFactoryInitialize(0, "enp131s0")
client = RobotStateClient()
client.SetTimeout(3.0)
client.Init()
code, services = client.ServiceList()
print("code:", code)
print([(x.name, x.status, x.protect) for x in services])
'
```

本次所需的主要状态一般应显示为：

```text
mcf         status=0
sport_mode  status=0
ota_box     status=1
```

以手机 App 实际显示的开关状态为最终依据，不要在机器人无人支撑时切换运动
服务。

## 11. 无后空翻接管验证

首次部署、修改配置、修改代码、更换机器人或更换 ONNX 后，必须先运行：

```bash
python -u deploy_real/deploy_real_backflip.py \
  enp131s0 \
  deploy_real/configs/go2_backflip.yaml \
  --wait-only
```

程序会依次执行：

1. 释放残留的内置运动模式。
2. 启动 500 Hz LowCmd 发布线程。
3. 等待并检查 LowState。
4. 保持当前姿态 1 秒。
5. 用 8 秒余弦曲线移动到训练默认 PD 目标。
6. 保持目标姿态 3 秒。
7. 检查承重姿态并标定足底压力基线。
8. 等待手柄 `START`。
9. 在 `phase=2` 终止相位启用 actor。
10. 持续检查 READY 条件，但拒绝所有 A 触发。

出现以下提示后按一次 `START`：

```text
[ARM] Press START to enable RL; SELECT aborts to damping
```

随后应看到：

```text
[POLICY] direct torque enabled at terminal phase; waiting for A
[CONTROL] WAIT-ONLY: A is disabled | SELECT=damping stop
```

`--wait-only` 中即使误按 A，也只会显示：

```text
[A] trigger rejected: --wait-only is active
```

不会执行后空翻。

## 12. READY 条件与实测站姿

当前 Go2 EDU 的终止相位稳定参考姿态为：

```text
[ 0.023,  0.827, -1.591,
 -0.019,  0.841, -1.595,
  0.079,  0.902, -1.669,
 -0.102,  0.904, -1.675 ] rad
```

关节顺序为：

```text
FL(hip, thigh, calf), FR(hip, thigh, calf),
RL(hip, thigh, calf), RR(hip, thigh, calf)
```

这是机器人承重后的实测平衡姿态，不等于训练配置中的零动作 PD 目标。
位置 PD 必须保留一定误差才能产生重力支撑力矩，因此不能要求承重实测角
严格等于 `default_angles`。

触发前必须同时满足：

```text
终止相位参考姿态的每关节误差  <= 0.10 rad
最大关节速度                    <= 0.50 rad/s
机身倾角                        <= 0.10 rad
足底压力                        >= 启动基线的 80%
上述条件连续成立                >= 1.00 s
本进程此前成功触发次数          = 0
```

全部满足后显示：

```text
[READY] one-shot backflip trigger conditions are stable
```

实测等待状态的典型指标为：

```text
倾角                  约 0.07 rad
估算力矩倍率          约 0.47--0.49
稳态最大关节速度      通常低于 0.50 rad/s
```

如果速度偶发超过 `0.50 rad/s`，程序会撤销 READY 并重新累计一秒稳定时间。
这是正常保护，不能通过修改代码绕过。

无翻转测试完成后，先扶住机器人，再按 `SELECT` 进入阻尼并退出。

## 14. 正式操作顺序

### 14.1 自动归位

程序首先显示：

```text
[1/3] Hold current pose for 1.0s
[2/3] Ramp to trained default pose over 8.0s
[3/3] Hold default pose for 3.0s
```

如果出现：

```text
Exit: safety: 默认站姿未收敛
```

不要继续。查看 `[STARTUP] measured q`、`target q` 和 `q error`，检查四脚、
保护绳、机身倾斜以及具体失败关节。

### 14.2 START 启用策略

出现：

```text
[ARM] Press START to enable RL; SELECT aborts to damping
```

按一次手柄 `START`。随后显示：

```text
[POLICY] direct torque enabled at terminal phase; waiting for A
[CONTROL] A=backflip | SELECT=emergency damping stop
```

### 14.3 等待 READY

必须等待最新日志出现：

```text
[READY] one-shot backflip trigger conditions are stable
```

并确认最新周期仍显示：

```text
gate ready
```

如果出现以下任一提示，不要按 A：

```text
gate terminal pose ...
gate joint speed ...
gate tilt ...
gate foot force ...
gate stable hold ...
```

### 14.4 A 触发一次

最新状态为 `gate ready` 时，按一次手柄 `A`。接受后显示：

```text
[A] BACKFLIP triggered at control step ...
[DIAG] 5-second capture started
```

触发后：

1. 不要再次按 A。
2. 不要再次按 START。
3. 所有人保持在安全区域外。
4. 让 actor 自动完成起跳、旋转、落地和恢复。

当前配置为：

```text
single_flip_only: true
```

每次进程只允许成功触发一次。如果 A 被安全门拒绝：

```text
[A] trigger rejected: ...
```

则机器人没有执行后空翻，也没有消耗单次触发机会。继续等待新的 READY，
不能绕过门限。

### 14.5 落地和恢复

两秒动作相位结束后显示：

```text
[BACKFLIP] phase complete; RL continues landing/recovery
```

此时 actor 仍在控制机器人。程序不会重置物理状态，策略会继续负责落地、
恢复和终止相位站立。

等待约五秒，查看：

```text
[DIAG SUMMARY]
```

重点保存以下指标：

- 最大关节速度及对应关节；
- 最大关节位置误差；
- 最大命令力矩和力矩倍率；
- `tau_cmd` 与 `tau_est` 跟踪误差；
- 最大机身倾角和累计俯仰角；
- 离地与重新接触时间；
- 最低电池电压和最大电流；
- LowState 延迟、推理时间和循环超时次数。

## 15. 正常退出

确认机器人已经落地并稳定后：

1. 操作人员先扶住机器人机身。
2. 按手柄 `SELECT`。
3. 等待程序发送一秒阻尼命令。
4. 等待 Python 进程完全退出。

正常退出日志类似：

```text
[STOP] sending damping commands for 1.0s
Exit: SELECT pressed
Loop: late=0, worst lateness=0.0 ms
LowCmd: sent=..., late=0, worst lateness=0.00 ms
```

退出后机器人处于阻尼状态，程序不会自动恢复宇树内置运动服务。必须先人工
支撑机器人，再通过手机 App 按现场安全流程恢复服务，或在确认安全后重新
启动机器人。不要在后空翻进程仍运行时开启 `mcf` 或 `sport_mode`。

## 18. 常见问题

### 18.1 网卡不存在

错误：

```text
enp131s0: does not match an available interface
```

检查：

```bash
ip -br addr
```

确认网线已经连接，网卡为 `UP`，并确认实际接口名称没有变化。

### 18.2 Ping 正常但收不到 LowState

检查：

- 当前环境是否为 `unitree_real`；
- `unitree_sdk2py` 是否可以导入；
- `mcf` 和 `sport_mode` 是否关闭；
- `ota_box` 是否启动；
- 是否有其他低层控制程序正在运行；
- DDS 数据是否出现在 `enp131s0`。

抓包命令：

```bash
sudo timeout 10s tcpdump -ni enp131s0 \
  'udp port 7400 or udp port 7401'
```

### 18.3 默认站姿未收敛

查看：

```text
[STARTUP] measured q
[STARTUP] target q
[STARTUP] q error
[STARTUP] max joint speed
```

检查四脚是否对称、保护绳是否承重、腿部是否被卡住、机身是否明显倾斜，
以及是否有单个电机异常。不要直接删除姿态门限。

### 18.4 长时间没有 READY

查看每行末尾的 `gate` 原因：

```text
gate terminal pose ...
gate joint speed ...
gate tilt ...
gate foot force ...
gate stable hold ...
```

只有所有条件连续满足一秒才会 READY。速度偶发超过门限会重新计时，这是
正常保护。

### 18.5 手机 App 无法控制

后空翻程序会使用 LowCmd 并释放内置运动模式。运行时不要同时使用手机 App
发送运动指令。退出后先扶住机器人，通过 App 安全恢复对应服务，必要时在
安全状态下重启机器人。
